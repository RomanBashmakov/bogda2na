## 2. Доступность и сетевая диагностика

- TCP-порт 443 открыт; ping ~42 мс, потерь нет.
- Сайт отвечает только по IPv4 (`curl -6` — нет маршрута).
- **Особенность защиты:** WAF/защита от перебора агрессивно фильтрует запросы:
  - POST на `wp-login.php` с User-Agent `curl/*` — **молча дропается** (TCP принят, ответа нет);
  - серии быстрых запросов — троттлятся (блок на ~1–2 минуты);
  - рабочая формула: браузерный User-Agent + заголовок `Referer` + паузы 15–30 с между запросами.

## 3. Авторизация и управление

| Параметр | Значение |
|---|---|
| Вход в админку | `https://2n-beads.art/wp-login.php` → **выполнен успешно** (302 → wp-admin, кука `wordpress_logged_in`) |
| Проверка панели | `wp-admin/` отдаёт «Консоль ‹ 2N — WordPress» (код 200) |
| REST- nonce | получен через `admin-ajax.php?action=rest-nonce` (живёт ~12–24 ч, обновляем) |
| Сессия | cookie-jar `/tmp/wp_ck2.txt` — вне проекта, в git не попадает, пароль в файлах не хранится |
| Учётка | `admin` (права администратора) |

**Подтверждённые возможности управления:** создание/редактирование товаров WooCommerce (цены, описания, фото, остатки, категории), записей, страниц, загрузка медиа, модерация комментариев — через REST API `wp-json` с cookie-авторизацией + `X-WP-Nonce`.

## 4. REST API (полный список namespaces)

`oembed/1.0`, `wp/v2`, `wc/v1`, `wc/v2`, `wc/v3`, `wc-admin`, `wc-analytics`, `wc/store`, `wc/store/v1`, `wc/private`, `wc-admin-email`, `wc-telemetry`, `wccom-site/v3`, `wp-site-health/v1`, `wp-block-editor/v1`, `wp-abilities/v1`, `jetpack/v4`

Ключевые следствия:
- **`wc/v3` доступен** — полноценное управление магазином (товары, заказы, купоны, отчёты) при наличии API-ключей (WooCommerce → Настройки → Дополнительно → REST API).
- **`wp-site-health/v1`** — можно запрашивать диагностику «Здоровье сайта».
- **Jetpack** установлен — вероятный источник блокировки не-браузерных логинов (модуль защиты от перебора паролей).

## 7. Рекомендации

### Безопасность (приоритет)
1. **Сменить пароль админки** — передан в переписке. Пользователи → Профиль → Новый пароль.
2. Создать **«Пароль приложения»** для автоматизации (Пользователи → Профиль → Пароли приложений) вместо основного пароля — отзывается одним кликом.
3. Убедиться, что `xmlrpc.php` закрыт (Jetpack обычно защищает; при использовании Jetpack-модулей он нужен).

### Контент и развитие
4. **Синхронизировать новинки из ТГ-канала в магазин** — сайт не обновлялся с апреля 2026, а канал живой (см. §6).
5. Настроить автоматическую выгрузку каталога (например, через `wc/v3`) для поддержки актуальности цен/остатков.
6. Связать канал и сайт взаимными ссылками: описание ТГ → сайт, футер сайта → ТГ-канал.
